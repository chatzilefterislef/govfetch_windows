# Ασφαλιστική Ενημερότητα (e-ΕΦΚΑ) — κατάσταση & παράδοση

Σημείωμα παράδοσης για συνέχιση σε άλλη συνεδρία ή σε άλλο μηχάνημα (Mac).
Ημερομηνία: 2026-08-20. Πλατφόρμα ανάπτυξης/δοκιμών: Windows 11.

## Κατάσταση: ΔΟΥΛΕΥΕΙ ΑΠΟ ΑΚΡΗ ΣΕ ΑΚΡΗ

Επιβεβαιωμένο ζωντανά, μία επιτυχής λήψη:

```
🔘 «Συνέχεια στο TAXISNET» → κωδικοί → «Αποστολή» (εξουσιοδότηση)
🔘 «Επιχείρηση/Πολίτης» → «Είσοδος»
🔘 «Αποδεικτικό Ασφαλιστικής Ενημερότητας»   (μενού πύλης eAccess)
🔘 «Αποδεικτικό Ασφαλιστικής Ενημερότητας»   (δεύτερο μενού, μέσα στην εφαρμογή)
✅ Η φόρμα του e-ΕΦΚΑ φόρτωσε (βήμα 7)
✓ Απόκτηση Αθλητή → ▾ Είδος 01 → 🔘 «Υποβολή»
🧾 Αριθμός αίτησης: Φ/2938671/2026
⏳ 15″ → 🔘 «Έλεγχος Αποτελέσματος» στη γραμμή του αριθμού → PDF
```

Δοκιμάστηκε με **μία** αιτία. Οι πολλαπλές αιτίες (ξεχωριστή υποβολή ανά αιτία,
με επιστροφή στο μενού ενδιάμεσα) ΔΕΝ έχουν δοκιμαστεί ζωντανά.

## Το ένα πράγμα που πρέπει να ξέρεις

**Η φόρμα πρέπει να ανοίγει από το ΜΕΝΟΥ, όχι με απευθείας URL.** Με απευθείας
URL η φόρμα ανοίγει κανονικά αλλά ο πίνακας «Στοιχεία Αιτούντος» μένει κενός,
και η υποβολή απορρίπτεται με «Ο Α.Φ.Μ. είναι υποχρεωτικό πεδίο» — μήνυμα που
σε στέλνει να ψάχνεις τη σύνδεση, ενώ η σύνδεση είναι μια χαρά. Αυτό μας
κόστισε τις περισσότερες ώρες.

Όλες οι υπόλοιπες παγίδες (radio αντί κουμπιών στην εξουσιοδότηση, κρυφά
dialog του PrimeFaces, κουμπί γλώσσας που κλεβόταν αντί για το «Σύνδεση»,
POST-reload που δημιουργεί διπλή αίτηση) είναι γραμμένες αναλυτικά στο
`CLAUDE.md`, ενότητα «Παγίδες που έχουν κοστίσει χρόνο». **Διάβασέ το πρώτο.**

## Κανόνες ασφαλείας που ΔΕΝ αλλάζουν

- **Μία υποβολή ανά αιτία, και δεν αναιρείται.** Αν αποτύχει κάτι ΜΕΤΑ την
  υποβολή, δεν ξαναϋποβάλλουμε: κατεβάζουμε από το ιστορικό με τον αριθμό.
- **Ποτέ `page.reload()` μετά την υποβολή** — ξαναστέλνει το POST.
- **Ποτέ κλικ σε «Έλεγχος Αποτελέσματος» χωρίς τον αριθμό μας.** Η λίστα δείχνει
  τις αιτήσεις 2 ημερών· λάθος γραμμή = λάθος έγγραφο με σωστό όνομα αρχείου.
- **Κανένα `value` πεδίου στο log.** Ο κωδικός πελάτη έχει ήδη διαρρεύσει μία
  φορά έτσι.

## Τι μένει

1. Δοκιμή με **πολλαπλές αιτίες** σε ένα τρέξιμο.
2. Δοκιμή σε **macOS** — δεν έχει τρέξει καθόλου εκεί μετά από αυτές τις αλλαγές.
   Στο Mac ο πακεταρισμένος Chromium δουλεύει, οπότε η `launch_browser()` δεν
   πέφτει σε Edge/Chrome· η λογική πλοήγησης δεν αλλάζει, αλλά οι χρονισμοί
   (AJAX, τα 15″ αναμονής) μπορεί να θέλουν ρύθμιση.
3. Τα διαγνωστικά screenshots ανά οθόνη (`gov_debug_efka_step*.png`) είναι
   πολλά· αν ενοχλούν, κράτησέ τα μόνο σε αποτυχία.
4. Δεν υπάρχει test για τη ροή του ΕΦΚΑ στο `tests/test_portal_logic.py` — οι
   έλεγχοι έγιναν με ad-hoc mock σελίδες. Αξίζει να μπουν μόνιμα.

## Πού είναι τι

| Τι | Πού |
|---|---|
| Όλη η ροή ΕΦΚΑ | `automation/myaade.py`, `download_asfalistiki()` και `_reach_efka_form()` |
| Οθόνες σύνδεσης | `_reach_efka_form()`, `_efka_consent()`, `_submit_gsis_form()` |
| Μετά την υποβολή | `_efka_confirm_submission()`, `_efka_fetch_result()` |
| Έλεγχοι φόρμας | `_efka_applicant_filled()`, `_labeled_box_checked()`, `_efka_validation_error()` |
| Σταθερές/URL | κορυφή του `myaade.py` (`EFKA_*`) |
| Logs & screenshots | Windows: `C:\tmp\` · macOS: `/tmp/` |
| Αριθμοί αιτήσεων | `<Πελάτης>_Αριθμοί_Αιτήσεων_ΕΦΚΑ.txt` δίπλα στα PDF |

## Πώς τρέχει

```bash
python run.py          # Windows: python, macOS: python3
```

Μετά <http://localhost:8000>. **Μην τρέχεις `uvicorn` απευθείας.**

Στο πεδίο «Ονοματεπώνυμο πελάτη» βάζε ΟΝΟΜΑ — μια φορά είχε συμπληρωθεί εκεί ο
κωδικός TaxisNet (πιθανόν από autofill) και κατέληξε στα ονόματα των αρχείων.
